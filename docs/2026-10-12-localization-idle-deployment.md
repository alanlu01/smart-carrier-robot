# 2026-10-12 定位、3F_NEW 與閒置功能版本

## 部署狀態

INA3221 仍接行充小電池，使用者確認尚未與底盤共用大電池。
因此 `home.enabled=false`、`home.battery_source_verified=false`，
`power_monitor.main_battery_source_verified=false`；不發送冒充大電池的
`/vehicle_battery/verified_status`。低電量返航程式已備妥，但不會以現有小電池
觸發停接單／返航。接線完成後需確認電壓與來源、測試，再明確啟用三項設定。
既有 INA 行充分類及電池顯示門檻未改動。

人流感知已啟用：無任務閒置 60 秒後到 (1.5, 3, 0) 觀察，
Nav2 碰撞檢查、即時雷達安全視野、定位就緒及停止確認通過後才自旋。
觀察後依現有 Person 偵測選擇三個待機點，不做任意人群追蹤／巡邏。
新任務會搶占觀察，取消動作確認結束後才能切換任務；冷卻 600 秒。
證據不足／旋轉被障礙阻擋時不臆測人流目的地。

## 地圖及座標

`navigation.launch.py` 預設使用 `maps/3F_NEW.yaml`；PGM 與 YAML 已納入版本控制。
原有其他地圖、雷達車體遮罩、速度、MPPI、相機 FPS、1060 核心與更新政策不變。
API 的服務點座標仍以後端訂單為準，本版只更動車載待機點與觀察／返航點。

| 車載待機點 | x | y | yaw |
| --- | --- | --- | --- |
| CYCU EE | 2.0 | 5.18 | 0 |
| 座位燈 | 1.4 | -5.3 | 0 |
| 座位 | 6.6 | -0.3 | π（180°） |

HOME=(0,0,0)，暫無實體基站，使用一般返航點 0.10m／0.10rad 容許值。
不是紙箱精密入庫、ArUco 或自動充電功能。
定位快取綁定 YAML+PGM 雜湊；切換地圖或舊快取沒有地圖識別時，同次開機
重啟不會套用未知地圖的舊位置。首次升級若要求人工定位，提供一次正確
2D Pose Estimate；之後可信位置會保存新識別。真正重新開機仍須擺在 (0,0,0)。

### 人流實際方位

以觀察點為中心、地圖 +X=0°、逆時針遞增，依待機點實際方向劃分最近扇區，
不是硬切 120°。理論邊界約：CYCU EE 22.09–173.20°，
座位燈 173.20–298.20°，座位 298.20–360° 與 0–22.09°。
實作以 15° 角度格計算各格多幀中位數，再取所屬扇區的平均密度，
補償扇區寬度差異；不是唯一人數統計。熱度相同選距離近者。
停靠 yaw 不改變扇區方向。

## 定位改動

- 輕度低分（現有 degraded 區間）且 AMCL covariance 健康、雷達／里程計／
  AMCL 新鮮時，可最多 3 秒、0.40m 或 3 個獨立地圖觀測的短暫半速觀察。
  持續低分、critical covariance、過期資料仍依原流程停止，不放寬硬性可信度。
- `/localization/speed_limit` 發送 0.5／1.0，fusion 取定位、語意安全限制的最小值，
  不相乘。曾收到定位訊號後逾時 1 秒會送零速；單獨啟動鍵盤測試且從未收到
  该訊號仍沿用舊模式。若停止 Nav2 後需測試底盤，請在停止確認後重啟 AI 管線，
  不旁路 watchdog。重新定位過程不以此倍率阻擋受控自旋。
- 自旋後取消額外車頭回正，仍確認完全停止後再判定定位。
- 有足夠獨立新鮮觀測、critical covariance 且約 8 秒改善不足 10% 時判定停滯。
  已改善者保留原收斂延長窗口，不盲目提前放行。
- 首輪全域失敗後先嘗試既有安全橫移；橫移不可行但完整四輪回授、原始與
  filtered 雷達、odom TF 及整圈安全視野通過時，可第二輪原地全域定位。
  第二輪自旋前再驗證一次，最多兩輪；未知視野不能視為空間，失敗維持人工介入。

## 預備的返航政策（目前未啟用）

- ≤10.0V 持續 15 秒停止新 claim，釋放未啟動任務；已開始任務可完成。
- ≤9.7V 持續 15 秒鎖定返航，安全取消服務導航，回報 failed 而非 done；
  正在實體取還時保持原地直到確認或原有 60 秒逾時，然後返航。
- ≤9.5V 停車、不自動移動；感測無效／過期不當成低電量或允許行駛。
- 到家需 Nav2 成功、即時 map pose 在容許值內、連續停妥 1 秒，不提早宣告抵達。
- 返航鎖定跨重啟保留。到家停妥、定位／資料正常、≥10.5V 持續 15 秒後，
  才允許人工呼叫 `/smart_carrier/reset_home_latch`（std_srvs/Trigger）。
  單純網頁解除、電壓回升、重啟都不能自動解除返航鎖定。

## 給網頁／API 隊友

這次不改 API schema、migration 或雲端部署；既有 released／failed／結果可靠重送繼續使用。

1. 地圖顯示若有待機標記，請同步上表三點與第三點 180°。服务點仍用隊友已更新的
   3F_NEW 座標，不用車載舊離線 LOCATION_DB 覆蓋後端。
2. 人流觀察屬閒置活動，不是顧客訂單，不應誤顯示配送完成。可選擇顯示車輛
   「前往觀察點／人流觀察／前往待機點」；目前車載 topic
   `/smart_carrier/optional_idle_state`，未新增雲端傳输。
3. 未來返航啟用後，若要後台解鎖按鈕，需具管理員權限、確認對话，
   API → robot command → ROS reset service → response／ACK 的可靠命令链；
   只有機器人檢查成功才更新 UI。不把雲端 accepting 改 true 當解鎖。
   **本版未提供此 API 路由或網頁按鈕**，需另協作串接。
4. 未來低電量接受狀態與返航原因可從 task_admission／optional_idle_state 串接；
   停接單但正在服務、等待取還、返航、返航失敗、已到家鎖定須區分。
   不把已釋放任務顯示 done；目前真實返航停用，正常下單不受小電池影響。

## 實車驗證及錄製

不自動啟動任何正式節點／車輛移動；部署只做建置、模擬／靜態回歸。
實車測試先空曠處、有急停人員，先確認正確地圖與 TF，再依序：

1. 一般單／多筆服務與三點停靠；取還仍三筆確認，结果被雲端接受。
2. 人靠近造成短暫低分是否半速且順暢，真正搬動／嚴重低分仍停止。
3. 搬動後恢復：停止、自旋、無額外回正；觀察 stall、兩輪上限與安全拒絕原因。
   不以撞桌椅或遮蔽雷達強迫二次移動。
4. 閒置超過 60 秒，觀察三個方向，確認三站選點與座位 yaw=π；過程插入訂單
   應安全取消觀察後接手，無人或證據不足不虛構目的地。
5. 目前不得以小電池測真實返航；大電池改接後先驗證來源與電壓，再做低壓
   模擬門檻、恢復及實體取還保護測試，不深度放電作驗證。

完整錄製（先前 topic 不減少，新增定位倍率）：

```bash
bash ~/dev_ws/src/smart-carrier-robot/tools/record_full_system.sh
```

記錄是否搬車、手動斷電、斷網、有人遮擋與操作時間。人流／返航 topics 未啟用時
沒有資料屬預期；錄製本身不啟動功能。
